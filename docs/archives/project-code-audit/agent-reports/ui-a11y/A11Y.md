# Accessibility gaps

Physical TalkBack / VoiceOver / large-text / RTL gesture = **Needs runtime**.
What follows is code structure only.

## What `ProductionUiAccessibilityContractTest` actually asserts

Source-string presence, not rendered semantics:

1. `WaxSealReveal` has `Role.Button`, `onClick(label = a11y)`, and
   `pointerInput(reduced, completed, holdMs)`.
2. Mafia `TargetPickerScreen` uses `.selectable` + `Role.RadioButton`,
   `validSelection`, and no `.clickable(enabled = target.enabled`.
3. Recovery overlays (`ReconnectingOverlay`, `HostDisconnectedOverlay`,
   `OfflineBanner`) contain `liveRegion`; listed activity sources contain
   `ParlorActivityIndicator`.
4. Whodunit/Mafia routers do not publish no-op `onTap = {}`; peer waiting
   is a non-click surface; Mafia night resolve is not in the MD router.
5. Home catalog is registry-driven; no coming-soon tile / strings.
6. App wires `languageTag?.let(AppLanguage::fromTag)`,
   `rememberSystemReducedMotion()`, `shouldReduceMotion(`;
   Settings can `setLanguageOverride(null)` and uses `.selectableGroup()`.
7. Host-lost peers `clearAndSetSemantics { }`; start-gate `when`;
   privacy overlay appears twice in the Whodunit router; privacy confirm
   is Destructive; reconnect overlay consumes pointer events.
8. Platform locale overrides are dispose-scoped.
9. No `.replace("%N$s")` format bypass in production Kotlin under the
   four UI roots.
10. Every `.clickable` / `.selectable` / `.toggleable` within 320
    characters includes `role = Role.`.
11. Named fullscreen surfaces have a minimum `.verticalScroll(` count.

Not asserted: contentDescription quality, focus order, TalkBack
announcements, contrast, 48dp targets except `ParlorButton`’s 52dp,
iOS swipe-back, Desktop keyboard, or unused composables.

## Roles / names

Strengths:

- `ParlorButton` requires `contentDescription` and `Role.Button`.
- Settings radios / switch have roles. Home settings link has a role.
- Wax seal has a one-shot semantics click besides hold.
- Target rows are radio buttons and drop stale ids.

Gaps:

| Gap | Evidence | Finding |
|---|---|---|
| `pressableSurface` is `Role.Button` with **no** contentDescription | `Pressable.kt`; used by case rows + vote candidates | `UI-005` |
| `CandlelitCover` / `HideScreen` / Mafia covers are full-screen clickable with no contentDescription | visible title/subtitle may be the name; tap-to-advance is implicit | `UI-006` |
| Vote candidate rows announce the player name only (no “vote for X”) | `VoteScreens.CandidateRow` | `UI-005` |
| Case picker rows have no distinct a11y action string | `WhodunitCasePickerScreen.CaseRow` | `UI-005` |
| `TargetPicker` submit/skip reuse visible label as contentDescription | weaker than other buttons, not unlabeled | note |
| Pause control visible text is `"II"` | description is localized | OK if AT reads semantics first |
| `ScreenHeader` back: description optional | all shipping call sites pass one | OK |
| Unused `name_back` / `join_cancel` / `case_picker_back` labels | chevron-only back | note |

## Live regions / overlays

Announced: home recovery cards, local-resume failure, offline banner,
reconnecting overlay (`Assertive` + `paneTitle`), host-disconnected,
Mafia setup validation (`liveRegion` on `MafiaSetupScreen`).

Host-lost: peer gameplay semantics cleared so the overlay is the only
interactive tree. Reconnecting overlay consumes blank-area pointers.

Privacy / pause / session-exit are fullscreen replacements (`paneTitle`),
not dialogs over live private content.

## Reduced motion

Wired: app setting OR system (`ANIMATOR_DURATION_SCALE == 0` on Android).
`ParlorMotion.forReducedMotion` collapses durations; ember cycle = 0.
`ParlorActivityIndicator` becomes a static ring.
`WaxSealReveal` tap-to-reveal + hint when reduced.

Not proven: every animation site reads `ParlorTheme.motion` (most
Crossfades do). Needs runtime for OS Reduce Motion on iOS.

## Large text / scroll

Contract requires verticalScroll on listed fullscreen covers. Several
game screens (`RoundTitleCardScreen`, `ClueRevealScreen`) use
`SpaceBetween` **without** scroll (`UI-007`). Home is a `LazyColumn`.

## Back / focus / iOS

Android system Back is centralized and delegated into games.
iOS interactive swipe and Desktop Escape are **not** installed
(`UI-008`). Leave affordance exists after a session starts; setup
screens rely on header chevrons only.

Predictive Back / `enableOnBackInvokedCallback` not present in the
manifest. Needs runtime.

## Privacy overlays (pass-and-play)

Whodunit: black `CandlelitCover` / `HideScreen` between private
dossiers; `PrivacyConcernAffordance` on Handoff/Hide; host can
`RequestReroll`. Multi-device uses the same ceremony for self only.

Mafia: equivalent covers + Reveal button (no wax seal, no reroll
dialog). Night actions also pass through Handoff → Gate → Hide.

Android Recents: API 33+ `setRecentsScreenshotEnabled(false)`; older
`FLAG_SECURE`. iOS: `NotifyAppInactive` exists; occlusion UI is
lifecycle, not this workstream.

AT risk: a screen reader can still read a revealed dossier on the
shared phone. Covers hide pixels, not the accessibility tree of the
dossier while it is showing. Needs runtime to judge whether that is
acceptable for pass-and-play.
