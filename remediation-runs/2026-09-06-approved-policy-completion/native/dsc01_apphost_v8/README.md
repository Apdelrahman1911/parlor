## Real iOS Settings prerequisite

After both complete local matrices, the app is terminated and the actual public
Settings app is opened on the runner-created Debug simulator only. UUID equality
and the exact synthetic device-name prefix are required. The public experiment is
`General → Language & Region → Add Language → Arabic → retain English primary`.
There are no global/per-app defaults writes, private URLs, language launch pins,
generic alert dismissals or retries of a completed semantic step.

Every bounded step logs known selector classes/counts, numeric frames and status.
The initial English-primary/no-Arabic state and final **uncovered preferred list**
must be observed. Final proof requires a hittable Language & Region navigation
bar, no picker search/keyboard/alert, enabled Add Language successor, and an actual
Arabic preferred cell positioned after English-primary and before Add Language.
An Arabic picker result above a still-mounted underlying page cannot pass.

Apple Support109358 documents this public flow; WWDC2019/403 describes per-app
choices for multilingual users, not a guaranteed two-language trigger on26.5.
Exact selector classes/English-primary action aliases are bounded candidates,
not undocumented API guarantees. Unknown/ambiguous controls or outcomes produce
a **named BLOCKED step**, never guessed success. The existing independent per-app
English choice → actual app AR → System → restart proof is unchanged, apart from
names on its two observation waits. A prerequisite PASS alone is not DS-C01 PASS.
