## Why this version exists

Apphost04 ran five XCTest cases (four UIKit PASS, matrix FAIL). Settings and
Whodunit completed, but after two catalog swipes the Mafia card tap was not
followed by the expected generic topology-picker selector. The complete source
path requires that picker and exact label. No raw target frame/callback/destination
receipt establishes whether scrolling, occlusion, or another cause lost that tap.
This version does **not** claim to have diagnosed an application defect or crash.

See `../dsc01_apphost_04_diagnosis/source-diagnosis-and-v7-proposal-01.json` and its
exact CMP1.10.3/Apple public-API research. Independent proposal research receipt:
`../../reviews/independent-apphost04-catalog-research-01.json`.

## Narrow changes

- Only the catalog-card activation uses the new helper; subsequent original
  Pass-and-Play/count/names/settings/Start interactions remain unchanged.
- A unique real public Button is observed in up to fourteen six-sample windows.
  Samples are separated by nonblocking 250ms expectations. A moving target is
  observed again; an inaccessible stable target permits a bounded real scroll.
- The helper measures the actual target, app, observer container and known tab
  frames in screen coordinates. It chooses a target-relative interior point
  excluding observer/top/tab areas and rejects nonfinite/negative/tiny geometry.
- Immediately revalidates the exact target frame, enabled/hittable state and
  coordinate. Exactly **one** physical tap exists, outside retry loops. Actual
  picker presence plus catalog/tab disappearance is required before proceeding.
- Public numeric metadata is retained in the Xcode log (96 rows/game,4096B/row,
  192KiB/game). No arbitrary labels/values, hierarchy exports or private screenshots.
- Fourteen pure hit-geometry/stability checks execute at the start of the same
  matrix XCTest. The runner requires their receipt and both catalog-entry receipts.
- OS failure diagnostics additionally count bounded known public label prefixes
  and at most four numeric frames. They never choose/tap an alternative selector.
  Exact missing OS controls remain **BLOCKED**, not inapplicable or passing.
