## Protocol and transport contracts (complete reads)

- `Protocol.kt`: exact 4.2 schema. Separate transactional admission, resume, and game-start barriers; peer command sequence versus host frame sequence; own-private/public atomic snapshots. Limits: command 32 KiB, public+private 256 KiB, control 8 KiB, total 272 KiB. Deprecated admission compatibility shape still exists: reachability requires transport tracing. Capability secrets appear only in protected handshake objects; safe handling depends on transport. Session nonce is explicitly separate from hidden role seed.
- `ProtocolValidation.kt`: strict major.minor and exact session/game/version/epoch; ASCII bounded IDs; peer sequence zero; positive host sequence; command header/message binding; snapshot revision/client-next sequence; start IDs, contiguous seats, distinct canonical names, paired content version/hash. Identity stamping is transport responsibility. Header validation does not establish membership or game-state semantics; callers must. `SessionStarting` starts host sequencing at zero while commit is positive. Opaque commit/ack start IDs are compared to offer by handshake, not these generic validators. Long overflow practicality and untrusted CBOR nested/length behavior need exact caller/library analysis if reachable.
- `RoomMessageCodec.kt`: CBOR strict unknown keys, encoded defaults, byte strings. Size checked before decode/after encode; not a semantic validator. Decoder behavior for malicious declared collection lengths is not yet established.
- `LocalRoom.kt`: defaults support non-resumable test transports; production security must come from concrete overrides. Critical caller contracts: closeAdmissions atomically freezes connected roster; retire revokes capability; terminal commit validates physical ownership; closeForRetry retains capability; explicit finalLeave/discard report failure, unlike best-effort lifecycle leave. Default broad catches preserve cancellation. Shared fallback lifecycle is always Active.
- `RoomTransport.kt`: discovery capability distinct from manual endpoint; metadata-only resume API; ordered lifecycle hooks; LAN failure truthfulness. HostConfig supports up to 17 remote participants (18 total) although generic SessionStarting caps 16: current shipping callers/game caps must be checked before reporting mismatch. Identity/game version validation is layered.
- `RoomInputPolicy.kt`: canonical trim, bounded UTF-16 length, well-formed surrogate pairs; ISO controls/FORMAT rejected, exact case-sensitive duplicate comparison; UI sanitization drops malformed sequences and avoids splitting surrogate pairs. Normalization of room codes is convenience only; protocol boundary uses exact alphabet.
- `PeerSessionRetryPolicy.kt`: successfully acquired replacement resets transient retained marker; explicit Resume survives; subsequent post-admission failure always retries Resume.
- Hash/ID platform actuals: JVM SHA-256/SecureRandom; Apple CC_SHA256 handles empty input without addressOf(0), SecRandomCopyBytes status checked. Equal-length digest comparison is full-loop; SHA-256 temp UTF-8 bytes zeroed. Long seed conversion uses all 64 bits. Rejection sampling avoids modulo bias. Managed String secrets cannot be guaranteed wiped; do not claim memory-erasure guarantees.
- `DiscoveredRoom`, `PeerEvent`, `RoomLifecycle`: contract/data types only; lifecycle distinguishes Active/Suspended/Resuming/Expired/Closed and peer versus host events.
